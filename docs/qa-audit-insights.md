## 📝 QA Audit: Summary & Critical Insights

### 1. Несоответствие спецификации Swagger 🛡️
> **Документация API содержит несоответствия (например, статус `500 Internal Server Error` там, где логика требует клиентских `4xx`). Тесты написаны по стандартам REST и OWASP — с приоритетом на логику и безопасность, а не на слепое следование текущей доке. Поскольку вызвать реальную 500 прямыми запросами к бэкенду невозможно, этот кейс замокан через Postman Mock Server. Автотесты успешно проверили поведение системы и структуру JSON при эмуляции критической ошибки сервера.**

---

### 2. Критичные уязвимости (Security) 🔴

> [!CAUTION]
> **BOLA & Broken Auth:** Отсутствует изоляция данных на уровне объектов. Запросы `PUT` и `DELETE` не проверяют владельца ресурса — Пользователь Б может модифицировать или удалить данные Пользователя А. Часть деструктивных методов доступна без валидного JWT-токена.
>
> **SQL Injection:** Эндпоинты фильтрации и пагинации уязвимы для инъекций, что открывает прямой доступ к манипуляциям с БД.

---

### 3. Производительность и стабильность 🟡

> [!IMPORTANT]
> **Performance Bottleneck:** Сервер ложится при нагрузке свыше 10 независимых потоков Newman CLI (вылетают ошибки `ECONNRESET`, хотя сервер должен возвращать `503 Service Unavailable` вместо сетевых обрывов).

> [!WARNING]
> **Rate Limiting:** Механизм защиты работает (отсечка на 21-м запросе), однако стабильность ответов при превышении лимита падает (появление ошибок протокола HTTP/2).

---

### 4. Final Conclusion ✅

> [!TIP]
> **Бизнес-логика системы работает корректно, но критически важно закрыть уязвимости в безопасности и исправить логику авторизации. Разработанный тестовый фреймворк готов к использованию в качестве регрессионного набора сразу после устранения обнаруженных багов.**
