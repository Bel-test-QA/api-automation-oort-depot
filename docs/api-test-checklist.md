# API Automation Framework: Security Audit, Stress & Logic | Oort Depot
## ☑️ Высокоуровневый чек-лист проверки REST API

| № п/п | Check List | Comments |
| :--- | :--- | :--- |
| 1 | **Контрактное и функциональное тестирование (Provider-driven, Swagger): позитивные проверки** | Гибридная проверка за один проход: сверка структуры JSON-ответа, обязательных полей и типов данных со спецификацией FastAPI Swagger  (единый источник правды) одновременно с валидацией бизнес-логики на позитивных сценариях (без дублирования запросов). |
| 2 | **Контрактное и функциональное тестирование (Provider-driven, Swagger): негативные проверки** | Гибридная проверка контракта и обработки ошибок сервера (`400`, `404`, `422`) при отправке невалидных данных, отсутствующих обязательных полей и неверных типов данных. |
| 3 | **CRUD-тестирование: позитивные сценарии** | Полный цикл операций со звездолетами, грузами и погрузками: создание (`POST`), чтение (`GET`), обновление статуса/данных (`PUT`), удаление (`DELETE`) с передачей `ID` между запросами. |
| 4 | **CRUD-тестирование: негативные сценарии** | Проверка негативных CRUD-кейсов: создание, чтение, обновление или удаление по несуществующему или уже удалённому `ID` (`404`), создание дубликатов, передача некорректных параметров. |
| 5 | **Интеграционное тестирование модулей** | Проверка взаимодействия основных модулей системы между собой (связка управления флотом звездолетов, складскими грузами и операциями погрузки). |
| 6 | **Сквозное бизнес-тестирование (E2E)** | Прохождение полного пользовательского цикла: от регистрации нового звездолета и добавления груза на склад до оформления операции погрузки и проверки итогового состояния системы после удаления этих сущностей из БД. |
| 7 | **Проверка сетевого и транспортного уровней** | Проверка обязательных HTTP-заголовков (`Content-Type`, `Accept`), обработки незащищённого HTTP (`301` редирект на HTTPS) и поддержки кодировок. |
| 8 | **Проверка безопасности: защита от SQL-инъекций** | Передача SQL-пейлоадов в параметры запроса и тело JSON для проверки защищённости БД от инъекций. |
| 9 | **Проверка безопасности: контроль доступа к объектам (BOLA / IDOR)** | Попытка изменить или удалить чужие сущности (звездолеты, грузы) по чужому `ID` с токеном другого пользователя (`403` / `404`). |
| 10 | **Проверка безопасности: аутентификация (Broken Authentication)** | Отправка запросов к защищённым эндпоинтам без токена авторизации (`401`). |
| 11 | **Проверка безопасности: защита от Mass Assignment** | Попытка передать в теле запроса закрытые системные поля (`is_admin`, `role`) для несанкционированного изменения прав или атрибутов объекта. |
| 12 | **Проверка безопасности: утечка технической информации (Verbose Errors)** | Проверка ответов при невалидных URL и спецсимволах на отсутствие чувствительных данных сервера (stack trace, системные пути (`400` / `404` / `422`). |
| 13 | **Производительность: проверка Rate Limiting** | Проверка срабатывания защиты от превышения частоты запросов при массовом создании и удалении сущностей (`429`). |
| 14 | **Производительность: нагрузочное и стресс-тестирование** | Проверка времени отклика на ключевых операциях (создание звездолета, обновление статуса, добавление груза, погрузка) и поведения сервера при пиковой параллельной нагрузке. |
| 15 | **Асинхронные события и логирование** | Проверка отправки и валидности структуры сообщений в брокере очередей (Kafka) при операциях погрузки, а также фиксации логов прогонов и ошибок (ELK). |
